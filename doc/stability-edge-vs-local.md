# 稳定性对比：本机终端 vs 国际边缘

对比窗口（两源重叠）：**2026-11-24 15:30 ~ 2026-11-25 03:28（CST）**，约 **12h**  
数据源(监控端)：本机 Kuma `status-v2` / 国际 UptimeFlare `uptimeflare-56u.pages.dev`

站点：

- **ali(pst)**：`PST-nav-menu` → `https://pst.xxx.com/...`
- **tunnel**：`Cloud-DSH-tunnel` → Cloudflare Tunnel 目标

## 结论（简）

- **本机终端**：pst 远稳于 tunnel（低延迟、零故障）；tunnel 抖动大、偶发 down。
- **国际边缘**：tunnel 更稳；pst 超时/520 多，可用率与延迟都更差。
- 路径不同导致结论相反：国内直连阿里友好，边缘到阿里链路差；边缘到 Tunnel 友好，本机经 Tunnel 出口差。

## 可用率（同窗）

口径：本机按心跳点 up/down；国际按**同窗内** incident 时长占比（`1 - 故障秒/窗口秒`），不用页面「总可用率」（其统计窗更长）。

| 探测端 \\ 目标 | ali(pst) | tunnel |
| --- | --- | --- |
| 本机终端 | **100%**（0 down / 284 点） | 98.57%（4 down / 279 点） |
| 国际终端 | 98.05%（13 次事件 / 约 840s） | **99.58%**（3 次事件 / 约 180s） |

## 延迟稳定性（ms）

| 探测端 目标 | ali(pst)                                    | tunnel                              |
| ------ | ------------------------------------------- | ----------------------------------- |
| 本机终端   | mean **234** / p95 329 / σ **76**           | mean 2158 / p95 4508 / σ **1935**   |
| 国际终端   | mean 1880 / p95 4796 / σ **1901**（含 10s 超时） | mean **696** / p95 1391 / σ **345** |

- **p95**：95% 的探测延迟低于该值；越大说明尾部越慢。
- **σ**：延迟标准差；越大说明抖动越强、稳定性越差。

## 一句话

同一时段：看 **国内可达性用本机看 pst**；看 **海外边缘可达性用 UptimeFlare 看 tunnel**——两者不可互相替代。
